# 压力首轮场计算的数值恢复

原控制进程 1020013 在完成 227/450 个频率后，因点发射频率位置 45
的块 CG 曲率矩阵失去厄米对称性检查而失败。原主进程和工作进程
1022601/1022602/1022603 均已确认退出。没有材料更新或 RF 评分结果。

原阶段模型显存采样峰值为 13530 MiB，未超过模型 16 GiB 限制。
GPU0 同时出现其他用户的 3502 MiB 占用，整卡一度超过 16 GiB；
不能把整卡读数当成本模型占用，也不能将本次异常归因为显存不足。

固定材料的正规方程在解析上厄米正定。原块方法需要对几乎相关的
11 个搜索方向进行小矩阵求逆；在迭代后期，这会放大有限精度误差。
这是与异常一致的数值机制解释，尚未通过保存下来的失败矩阵直接
证明，不是对数据可辨识性的结论。

新 `pressure_stable_cg.py` 在一个 GPU 批次内分别求解全部 11 个
发射，使用 ||C P d||²+lambda||S P d||² 计算正曲率，不再求逆发射
方向的 Gram 矩阵。真实残差检查后重启；仅接受每个发射实际增广
目标不增的场。数值停滞仍报告未收敛，原请求容限 0.003 保持不变。

合成 CPU 的 11 个近线性相关右端问题相对解误差为 1.36e-15，
各发射目标均不增。这里没有患者传播或材料有限差分实验。

恢复程序 `nsrno.resume_pressure_field` 预检查确认：180 个平面波和
47 个点发射频率已完整提交；其不可变 R/D、代数标记和正权重齐全。
其余 223 个频率继续计算。已初始化的代数 1 使用原始 R/D，未启动
的代数 0 使用原来的完整零乘子，避免把 Y_base 再加到右端。

新控制进程为 1169771，工作进程为 1170030/1170032/1170033。
完整检查点为 `step001/field_partial_resume.json`，源码和权重保存在
`source_stable_field_step001`。新程序已实际越过原失败频率；首批任务
仍有少数发射未达容限，均保留记录。它没有证明三参数已经恢复。

原块 CG 日志、异常、227 个结果和旧资源报告保留。后续使用全部
450 个频率进行同样的材料统计、条件材料更新、乘子更新、原生 RF
评分和独立材料图评价。当前恢复程序及其源码清单全部冻结。
